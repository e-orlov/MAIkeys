# Сквозной тест на реальных ключевых словах, 20 ноября 2026

Тест шёл через браузер на живом сервере (порт 3000) с настоящими Google Suggest, Google Ads API и Groq. Я проходил весь путь: seed в Input, подсказки, объём, концепты, фильтры Include/Exclude, бренды, вопросы, экспорт. Каждый шаг проверял по данным в таблице, а экспорт сверял с таблицей ячейка за ячейкой.

Окно браузерной панели было узким (586 px). Это важно для пункта про экспорт ниже.

## Что прошло без замечаний

- Автоподсказки: 109 из 116 запросов вернули подсказки. Семь вернули пустой список (wen, bis wann, weshalb, woran, wobei, wodurch, wonach + kaffeemaschine). Приложение помечает их ❌. Я проверил напрямую: Google отвечает пустым массивом, это не сбой.
- Объём: в прогоне A данные получили все 1236 строк, у 717 есть история за 48 месяцев, у 519 объём 0. Одинаковые ключевики в разных строках получили одинаковые данные (расхождений 0).
- Ответ `/api/ideas` против таблицы (прогон B): сравнил 11 000 значений по 1000 строкам. Десять полей совпали полностью, концепты тоже (расхождений 0). Единственное отличие описано ниже (cpcAvg).
- Бренды: 214 из 214, 261 из 261 и 80 из 80 ключевиков классифицированы, 0 ошибок, 5 запросов к Groq на три прогона.
- Вопросы: 214 из 214, 259 из 259 (2 однословных пропущены по правилу) и 80 из 80. Все заканчиваются на «?» и начинаются с заглавной.
- Живое ожидание при лимите токенов: интерфейс показывал «Waiting 30 s (normal, nothing to do)» с обратным отсчётом, запросы после паузы проходили.
- Экспорт, ячейка за ячейкой: 4880 из 4880 ячеек (прогон A) и 1720 из 1720 (прогон C) совпали с таблицей. Фильтры Include/Exclude, три состояния фильтра брендов и поле Search действуют на экспорт так же, как на таблицу. Название файла: `wasserkocher-20261120073236.csv`.
- Ошибки JavaScript на странице: 0. Все запросы к `/api/...` вернули 200.

## Дефекты, найденные и исправленные в ходе теста

1. **Экспорт терял колонки, которые Responsive скрывает на узком окне.** В прогоне A я отметил в «Column visibility» все 20 колонок, а CSV вышел с четырьмя: Keyword, Search, Domain и ряд за 48 месяцев. Причина: таблица имеет класс `dt-responsive`, расширение Responsive прячет не поместившиеся колонки через `display:none`, а экспорт брал колонки по селектору `:visible`, то есть по DOM. На экране при этом в колонке «Column visibility» стояли галочки. После исправления экспорт берёт колонки, отмеченные в «Column visibility». Проверено в прогоне C: на экране Responsive скрыл 12 из 20 колонок, в CSV все 20. Если отмечено 6 колонок, в файле ровно 6 плюс ряд за 48 месяцев.
2. **Итоговая строка Ads ideas показывала неверное число.** Таблица содержала 1000 строк, а статус писал «98 results». Счёт брался через DataTables `search: 'applied'`, который отстаёт от строк, добавленных без перерисовки. По тому же счёту проверялся лимит результатов, поэтому он мог не сработать вовремя. Теперь строки считаются из данных. В итоговую строку добавлено замечание, что у Google больше идей, чем 1000 на запрос (API вернул `more: true`).
3. **«Get concepts» тратил запросы впустую.** В прогоне A первые три запроса (seed «kaffeemaschine», три страницы идей) покрыли 167 ключевиков. Следующие 17 запросов добавили две строки: seed выбирался из первого слова, и в seed попадали «wie», «welche», «warum», «was», «wer», «wann», одиночные буквы v, l, k. Ещё 476 ключевиков с объёмом 0 не имели шансов, потому что в Keyword Planner их нет. Теперь:
   - ключевики с объёмом 0 не запрашиваются;
   - вопросительные слова, предлоги и слова короче трёх букв не берутся в seed;
   - запасной seed берётся по убыванию объёма;
   - запросы прекращаются после четырёх подряд, не принёсших новых строк, с объяснением в блоке.

   На тех же данных прогона C: 14 запросов вместо 20, покрыто 58 ключевиков вместо 41 (49 с концептами вместо 27).

## Качество ответов LLM

Проверял вручную: примерно 43 пары «ключевик → вопрос» из прогона A, все классы брендов трёх прогонов, остальные вопросы только автоматически (формат).

Бренды:
- Класс 2 везде верный: 9 из 9 для Tchibo, 17 из 17 для Bosch (все 17 ключевиков с «bosch»), 3 из 3 для WMF.
- Явные промахи (класс 0 вместо 1): «v zug kaffeemaschine test», «k fee kaffeemaschine entkalken», «l or kaffeemaschine entkalken». Это бренды V-Zug, K-fee и L'OR, разбитые пробелом из-за префиксов a-z. При этом в вопросе для «k fee …» модель написала «K-Fee», то есть бренд узнала, но классифицировала иначе.
- Непоследовательно с магазинами: в прогоне B «media markt» и «amazon» получили класс 1, а в прогоне C девять ключевиков с dm, edeka, action, tedi, aldi, media markt, rossmann, lidl, amazon получили класс 0.
- Спорные: «stiftung warentest», «chip», «faz», «ökotest» (издания и организации) модель всегда относила к классу 0.

Вопросы:
- Шесть ключевиков в прогоне A уже были вопросами и вернулись практически без изменений (правило 6 из вашего промпта).
- Грамматика: «Welche kaffeemaschine ohne Mahlwerk ist Testsieger?» (существительное со строчной буквы), «Welcher Vollautomat-Kaffeemaschine-Test ist aktuell?» (неуклюжая конструкция).
- Смысловые добавки: «kaffeemaschine test vollautomat» превратился в «…hat im Test gut abgeschnitten?» (добавлено «gut»), «krups kaffeemaschine f 309 08 proaroma» в «Welche Eigenschaften hat…» (намерение стало информационным).

## Концепты Google: что реально покрывается

- При запросе с одним seed API отдаёт концепты почти для всех идей (999 из 1000 в прогоне B). Формат один: у каждого концепта три поля (название, название группы, тип группы), других полей нет. Типов: BRAND 501, NON_BRAND 413, OTHER_BRANDS 137, без типа 382 (1433 концепта на 1000 ключевиков).
- Строки из автоподсказок покрываются плохо. В прогоне A из 615 уникальных ключевиков с объёмом концепты получили 167 (27 %). Остальные не входят в списки идей ни одного из проверенных seed: это длинный хвост («kaffeemaschine entkalken» с 12 100 запросов в месяц тоже не вошёл в список идей для «kaffeemaschine»). В прогоне C финальная версия покрыла 49 из 104 (47 %).
- Seed запроса Google не аннотирует. Строка, использованная как seed, остаётся без концептов, и блок это объясняет.

## Ошибки в самом тесте (мои)

- Фильтры Include/Exclude из прошлого сеанса восстановились из localStorage, и первый запрос объёма в прогоне C ушёл только по 60 отфильтрованным строкам из 203. Я сбросил фильтры и повторил шаг. Приложение вело себя правильно.
- Первая проверка экспорта в прогоне A использовала `:visible` для готового списка колонок и поэтому показала проблему №1 из списка дефектов. Это нашло настоящую ошибку, но в нескольких моих скриптах я потом несколько раз терял результат из-за таймаута инструмента (45 секунд) и перезапускал шаги по опросу.
- В проверке на макете Google Ads я сначала использовал названия «nike laufschuhe sorte N», которых нет в макете, и ошибочно посчитал это дефектом. Данные исправлены, тест прошёл.

## Что не проверено

- Кнопка «Copy» (буфер обмена): содержимое можно получить через `exportData`, но саму вставку в буфер из панели прочитать нельзя. CSV-кнопки проверены через перехват файла, фактическая запись в папку «Загрузки» не проверялась.
- Реальные ошибки 429 и 5xx от Groq и Google. Их тексты проверены на макетах с теми же форматами сообщений (отдельный прогон раньше).
- Все 214 + 259 + 80 вопросов вручную. Вручную просмотрено около 43 пар из прогона A.
- Колонка с классом бренда в экспорт не попадает по вашему решению (фильтр только скрывает строки). Поля `brand`, `brandFor` и сырой массив `concepts` на строках остаются без собственной колонки. Содержимое `concepts` целиком есть в трёх колонках концептов.
- Ключевики, начинающиеся с `=`, `+`, `-`, `@`, экспортируются как есть (Excel может принять такую ячейку за формулу). Не менялось, ждёт вашего решения.
